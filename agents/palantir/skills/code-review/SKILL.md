# Skill: Code Review

## When to use
Use when reviewing PRs, diffs, refactors, migrations, and architecture changes.

## Procedure
1. Identify the intended behavior.
2. Read tests first.
3. Inspect correctness, edge cases, coupling, security, and performance.
4. Prefer minimal, actionable patches.
5. State risks clearly.

## Output
- Summary
- Bugs or risks
- Missing tests
- Suggested patch
