# Skill: Testing

## When to use
Use before merging code, changing behavior, or refactoring.

## Procedure
1. Identify public behavior.
2. Cover happy path, edge cases, failure cases, and regressions.
3. Prefer fast deterministic tests.
4. Avoid testing implementation details.
5. Run the smallest relevant test set first.

## Output
- Test plan
- Missing coverage
- Commands to run
